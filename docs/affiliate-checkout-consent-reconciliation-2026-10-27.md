## Immediate checkout critical gap

This is a privacy-safe default, NOT verified affiliate attribution. It can lose payable partner credit for a buyer who comes directly from a partner video.
- Whop's documentation for a plain HTML embed uses `data-whop-affiliate` from `?a=`, but **that recipe is not verified for the exact `@whop/elements-react@1.9.0` Checkout API**. - Backend PR #12 can create a Whop `checkoutConfigurations.create({affiliate_code, ...})` with idempotency and event metadata after server/provider validation; its sandbox-only `embeddedSessionId` proposal still needs API compatibility and real Sandbox testing. - Distinguish (a) consented and server-verified immediate referral, (b) consented Audit observation + authorized delayed checkout, (c) no consent/direct, (d) conflicted/withdrawn/expired, (e) provider-side affiliate dispute. ## Native affiliate checkout bridge now staged (nonproduction only)

Additional isolated source changes add `src/affiliate-native-session.ts`, `src/components/VerifiedAffiliateCheckout.tsx`, and `src/app/checkout/affiliate/[plan]/page.tsx`. The server-to-server `/api/checkout` continuation only issues the native cookie when the trusted backend explicitly reports `affiliateLinked=true`, the correct `planId`, a valid `ch_...` Whop `embeddedSessionId`, and a provider-confirmed configuration URL; raw affiliate-code parameters never create native sessions. A 10-minute AES-256-GCM token is stored solely in a `__Host-` secure HttpOnly SameSite=Lax cookie; no email, affiliate code, or personal Audit answers enter the encrypted payload. Tampering, expiry, wrong environment, wrong provider host and invalid configuration fail closed. The actual Whop Elements component renders `<Checkout checkoutConfiguration={id}>`, with verified Whop-hosted configuration as an **attributed emergency fallback** if Elements fails. Purchase confirmation remains the SaaS's Whop-authoritative membership verification, never a browser callback.

This path is **OFF by default** and needs all of: `FRAMELEADS_AFFILIATE_NATIVE_EMBED_ENABLED=true`, `FRAMELEADS_AFFILIATE_CONTINUATION_BRIDGE_ENABLED=true`, `AUDIT_CHECKOUT_CONTINUATION_ENABLED=true`, exact Vercel/Whop environment match, valid 64-character lowercase-hex `FRAMELEADS_AFFILIATE_NATIVE_COOKIE_KEY`, and the pre-existing native Whop plan/terms gates. Backend must return a verified provider checkout configuration ID from its own disabled `WHOP_EMBEDDED_SESSION_BRIDGE_ENABLED` gate. No live key has been set or created. The optional backend production mode also requires `WHOP_EMBEDDED_PRODUCTION_VERIFIED=true` after merchant/provider acceptance; absence retains the verified Whop-hosted checkout. There is **no release approval** to toggle any of these settings.

**Still not ready for direct video-to-Buy-Now affiliate traffic:** a new visitor's `?a=` must first acquire legal, server-issued affirmative referral consent and a securely bound server receipt. The current normal plan-based checkout and generic hosted fallback do **not** do that; never assume an immediate checkout preserves a partner commission. Codex or an approved development session can implement the direct-referral issuance/eligibility system only after the independent privacy decision and authorized durable RPC/schema are finalized. Do not abuse the encrypted continuation cookie as a way to convert a raw `?a=` into verified affiliate status, and do not make the customer complete an Audit merely to unlock ordinary purchasing.
